# RentKoa 功能介绍

版本：2026-10-01 · 作者：wenhan  
[在线图文版](https://wenhanweime.github.io/portfolio/#/project/rentkoa) · [产品网站](https://www.rentkoa.xyz/)

## 为什么做 RentKoa

我自己在小红书上接过推广。一单只有一两百元，也可能要花三五天沟通选题、报价和稿件。品牌要找人、讲需求、等回复；创作者要判断合作是否适合自己，再反复确认怎么写。

所以我做了 RentKoa，尝试让 Agent 协助双方找人、谈合作、准备内容。KOA 来自 KOL + Agent：创作者的分身了解账号资料和报价，品牌的 Agent 则根据推广需求推荐人选、准备邀约。

品牌可以在 RentKoa 上找创作者、发邀约、跟进合作。创作者则可以根据自己的账号资料创建 AI 分身，让它协助回答品牌的问题。下面用九张界面截图，介绍这些功能具体怎么用。

## 适合谁用

| 使用者 | 需要准备什么 | 可以做什么 |
| --- | --- | --- |
| 品牌或有推广需求的人 | 产品说明、目标人群、预算、内容形式 | 筛选创作者、发送邀约、查看回复、准备内容 |
| 中小创作者 | 公开主页、内容定位、最低报价 | 创建分身、回复邀约，减少反复介绍账号和报价的时间 |
| 日常做内容的人 | 关注的领域和参考账号 | 参考其他创作者的做法，准备文案和拍摄提纲 |

## 一次合作的流程

创作者创建分身，品牌填写推广需求。有了双方的资料，系统就能推荐创作者，由品牌选择并发出邀约。合作流程如下，内容最终仍由人来完善和发布。

```mermaid
flowchart LR
  A[创作者主页截图] --> B[分身资料与报价]
  C[品牌需求与预算] --> D[候选推荐与理由]
  B --> D
  D --> E[品牌选择并发出站内邀约]
  E --> F[创作者接受 / 协商 / 拒绝]
  F --> G[投放记录与跟进]
  G --> H[内容方向与草案]
  H --> I[人工完善、确认与发布]
```

例如，要推广一款 AI 陪伴产品，品牌可以先写清“希望向独居青年介绍睡前聊天功能”，再查看推荐的创作者是否合适。看过推荐理由和参考报价后，品牌选择人选并发出邀约。创作者在收件箱回复，品牌则在“我的投放”里查看回复、跟进合作。

## 其他功能

- **浏览创作者：** 首页可以按分类筛选、用关键词搜索，或按热度和更新时间排序。创作者卡片提供代表笔记和原始主页链接，品牌可以点开了解具体内容。根据推广需求推荐人选的功能见第 4 节。
- **分享分身主页：** 完成第 1、2 节的创建和设置后，创作者就有了可以单独分享的主页，展示代表内容、采集时的粉丝数、参考报价、账号定位和合作入口。
- **与分身聊合作：** 品牌可以向某位创作者的分身提问，讨论合作形式和推广目标。回答会参考账号资料、人设、基础报价和最低报价，服务器会保存对话记录。入口见第 7 节。
- **估算报价和收益：** 上传主页截图后可以查看参考报价，公开主页和收益页面也提供估算。收益页面根据估算单价、假定接单频次、服务费和成本计算结果，供创作者了解不同条件下可能的收入。
- **更新资料和灵感：** 推荐列表可以按需更新采集到的公开内容，灵感池会定时刷新。如果没有可用的新图片，页面会显示缺图提示或替代封面。

## Agent 如何参与合作

### 先了解品牌需求和创作者资料

创作者的分身需要了解账号背景、内容领域、人设和报价。品牌的 Agent 则需要知道产品是什么、想推广给谁、预算多少、希望做什么内容。系统分别保存这些资料，在推荐人选和讨论合作时使用。

我在面试中提到，希望根据少量公开信息创建一个能参与合作的分身。目前，系统能识别主页截图里的基本资料，创作者也可以自己修改人设；仅凭截图还做不到完整理解一个人。

### 记录每位创作者的合作进度

一个推广任务可以邀请多位创作者，每位创作者的邀约和回复会分别记录。品牌因此能在同一页面看到谁还没回复、谁已同意、谁正在协商。

| 记录类型 | 保存的信息 | 对应功能 |
| --- | --- | --- |
| 创作者档案 | 名称、采集时的粉丝数、领域、人设与报价 | 分身设置、公开主页、推荐和对话 |
| 投放任务 | 产品、目标、预算、人群、形式和要求 | 一键推广、我的投放 |
| 候选创作者 | 推荐理由、匹配分数、预估报价、合作进度 | 推荐卡片、进度列表 |
| 邀约消息 | 文案、发送时间、回复与处理状态 | 收件箱、催促提醒 |
| 商务对话 | 创作者资料、品牌需求、历史消息 | 与分身聊合作 |
| 内容方案 | 标题、开头、大纲、封面、镜头与标签 | 内容草稿、灵感方案 |

### 什么时候调用 Agent

我最初设想的是：有新任务、新消息或合作进展时，再让 Agent 处理。目前，推荐和对话在用户操作后触发，灵感池定时刷新。邀约是否超时，则在系统读取投放记录时检查。

这里用 Agent-to-Agent 描述品牌 Agent 和创作者分身参与合作的方式。是否兼容标准 A2A 协议，目前还没有验证。

## 目前能用的功能和待完善的部分

- 目前可以创建和设置分身、分享主页、预览推广需求、查看推荐、发送和回复站内邀约，以及跟进合作、准备内容草稿。另有报价和收益估算，供创作者参考。
- 目前有一条自动处理规则：邀约发出 24 小时后，如果没有收到拒绝或协商回复，系统会将其标记为已同意。系统在读取投放记录时检查是否超时；两次催促至少间隔 6 小时。自动标记不代表创作者本人已经确认合作。
- 合作草稿目前按三类模板生成。多轮审稿、修改记录、站外自动发布、付款结算和推广效果统计，还没有确认能完整走通。内容仍需人工审核和发布。
- 匹配分数、相似度、报价和收益都是模型或规则给出的估算，不代表真实成交、实际收入或推广效果。

另外，使用时有三点需要说明：

1. **发送邀约要用“一键推广”。** 这个入口可以保存任务、发送站内邀约，让创作者在收件箱回复。卡片上的“请他推广”可以准备邀约、与分身对话，但其中的发送按钮目前只显示提示，不会真的把邀约发给对方。
2. **超出预算后仍然可以发送。** 页面会显示已选创作者的合计费用，并在超预算时提醒，但不会阻止发送，品牌需要自行确认费用。
3. **页面数字需要结合来源理解。** 采集到的创作者档案数量不等于注册人数；相似度和预估收益也不能说明实际推广效果。这些数字不作为项目的业绩数据。

## 这个项目是怎么做出来的

做 RentKoa 的想法来自我自己接推广的经历。我先梳理了品牌找人、创作者接单的过程，再完成页面、后端、分身对话、合作进度管理和上线部署。我想试试：如果 Agent 知道品牌要推广什么，也了解创作者的内容和报价，能不能帮双方少花一些时间沟通。

- 梳理品牌找人和创作者接单的流程，设计页面，让双方能查看合作进度。
- 用 React / TypeScript 开发界面，编写后端 API，实现账号资料管理、创作者推荐、分身对话、站内邀约和内容工具。
- 为分身准备对话所需的资料和报价要求，设计推广任务、创作者、邀约与回复的数据结构。
- 完成上线部署，并根据使用中遇到的问题，继续调整数据采集、登录、内容推荐和跟进流程。

项目使用 React、TypeScript、Tailwind、Next.js API 和 Prisma / PostgreSQL。不同功能可以接入不同的模型：早期使用过 Google GenAI，目前商务对话和图像识别通过兼容接口调用模型，内容方案有单独的模型调用逻辑；调用失败时会使用模板。

## 面试里提到的想法，对应哪些功能

| 面试里讲到的事 | 在产品中的体现 | 对应章节 |
| --- | --- | --- |
| 小额推广也会花很多时间沟通 | 把需求和报价写清楚，提前准备邀约 | 第 3、4 节 |
| 品牌给出预算和目标，寻找创作者 | 推荐人选、由品牌选择、计算合计费用 | 第 3、4 节 |
| 分身了解创作者的风格和资料 | 识别公开资料、允许编辑人设，对话时参考账号背景和报价 | 第 1、2、7 节 |
| 收到消息或任务后，Agent 再继续处理 | 记录邀约、回复和合作进度，支持后续跟进 | 第 5、6 节 |
| 让 Agent 参与起草、审稿、修改，最后发布 | 目前提供模板草稿，完整的审稿、修改和发布流程仍待验证 | 第 6 节与“目前能用的功能和待完善的部分” |
